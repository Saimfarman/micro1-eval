# Project contracts

This document freezes the interfaces that later phases must preserve. The
repository implements M1-M3 transaction histories and a separate M4
register-history format. The existing M1-M3 history format is unchanged.

## Domain contract

- `evalkit.domain.history.parse(text)` parses a strict history.
- `evalkit.domain.history.print_history(history)` emits canonical text.
- `evalkit.domain.linearizability.parse_register(text)` parses a strict M4
one-register history and `print_register` emits its canonical form.
- `evalkit.domain.oracle.reference.ref_verdict(history, module)` returns the
  independent reference verdict.
- `evalkit.domain.oracle.rules.check(history, module)` returns a JSON-friendly
  verdict, certificate fields, and derivation.
- `evalkit.domain.oracle.o3.check(history, module)` is the isolated Z3-backed
  checker for M1-M4 and does not import O1 or O2.
- Modules are named `M1`, `M2`, `M3`, and `M4`.
- Expected answers are generated by oracle code; they are never typed into a
  task by a model.

## Task contract

Every task JSON record must contain:

```json
{
  "id": "T01",
  "module": "M1",
  "control": false,
  "status": "final",
  "verified_by": ["oracle implementation"],
  "history": "canonical history text",
  "prompt": "model prompt",
  "expected_verdict": "valid"
}
```

Generated tasks may add difficulty, provenance, rubric, derivation, and control
relationship fields. Placeholder or draft tasks are not eligible for a final
run.

Phase 2 final tasks also carry `canonical_hash`, `expected_certificate`, and
the complete `verified_by` oracle list. The hash is computed from the module and
canonical history; duplicate hashes are invalid. Expected certificates and
derivations are recomputed during validation rather than trusted from JSON.

## Attempt and grade contract

An attempt is written before grading and includes the exact prompt, requested
and returned model IDs, settings, response text, finish reason, usage,
latency, provider response ID, creation time, and content hash. A grade
includes the score, pass flag, criterion-level results, grader method, and
expected/observed verdicts. Raw attempts are immutable.

## Reproducibility contract

`verify` checks manifest coverage and hashes, `replay` grades committed raw
outputs without network access, and `reproduce` combines integrity checking,
replay, and report generation. Files are authoritative; SQLite is a derived
index rebuilt by manifest-aware ingest and never replaces missing evidence.

## API contract

The approved backend target is Quart with JSON endpoints under `/api`, an
OpenAPI document, RFC problem responses, security headers, and no provider
secrets in responses. The initial endpoint families are health, metadata,
tasks, models, runs, results, attempts, failures, grader reliability, and
integrity.

## Frontend contract

The approved frontend target is component-based React + Vite + TypeScript +
Three.js. Every visualization must have a 2D and table equivalent, and no
feature may require WebGL, JavaScript from a CDN, or a provider API key.
